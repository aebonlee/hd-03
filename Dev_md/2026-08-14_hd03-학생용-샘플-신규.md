# 2026-08-14 — hd-03 학생용 회원가입 실습 예제 신규

현대건설 수업에서 학생들이 복사해 실습할 예제를 만들었다.
강사용 완성본은 `hd-08`이고, 이것은 그것을 **학생이 자기 손으로 완성하도록** 다시 짠 것이다.

## 왜 hd-08을 그대로 주면 안 되나

`hd-08`의 `index.html`에는 회사 공용 Supabase 프로젝트(`hcmgdztsgjvzcyxyayaj`)의
URL과 publishable 키가 fallback으로 박혀 있다. 학생이 그대로 복사해 배포하면
**학생 사이트의 가입이 전부 회사 운영 프로젝트로 들어온다.**
738명이 들어 있는 통합 auth 풀에 실습 계정이 섞이고,
접두사를 안 바꾼 학생들끼리는 서로의 `hd08_profiles` 행을 덮어쓴다.

대표 확정: **학생은 각자 무료 Supabase 프로젝트를 만든다.**
그래서 이 예제는 키 자리를 비워 두고, 비어 있으면 화면이 안내를 띄운다.

## 리포 위치

`hd-02`에 넣으라는 지시였으나, 확인해 보니 hd-02에는 이미
"코드월드 · 프로그래밍 학습 플랫폼" 예제(HTML/CSS/JS 분리, 검색·필터·북마크)가 들어 있었다.
덮어쓰면 그 수업 자료가 사라지므로 보고했고, **비어 있던 번호 `hd-03`으로 확정**했다.

hd 시리즈 현황: 01, 02, 03(신규), 05, 06, 07, 08 — 04는 여전히 비어 있다.

## hd-08과 무엇을 다르게 했나

| | hd-08 (강사용) | hd-03 (학생용) |
|---|---|---|
| Supabase 키 | 회사 프로젝트 하드코딩 | **빈 값** + 설정 안내 화면 |
| 접두사 | `hd08_` | `hd03_` |
| 배포 | Actions 워크플로 + 리포 변수 주입 | **Pages main 루트** (워크플로 없음) |
| SQL | 옛 스키마 이관(RENAME) 포함 | 신규 생성만 |
| 검증 하네스 | 리포에 포함 | 제외 (로컬에서만 돌림) |
| README | 개발 메모 | **수업 안내서** |

**인프라를 일부러 걷어냈다.** Actions·리포 변수·마이그레이션은 이 수업의 주제가 아니다.
학생이 건드릴 파일은 `index.html`과 `supabase/schema.sql` 둘뿐이어야 한다.

## 설정 안내 오버레이

빈 값으로 `createClient()`를 부르면 그 자리에서 죽어 **페이지가 통째로 하얘진다.**
학생이 처음 열었을 때 하얀 화면을 보면 무엇이 잘못됐는지 알 길이 없다.

그래서 두 가지를 했다.

1. 미설정이면 더미 URL로 클라이언트를 만든다(예외 방지). 어차피 오버레이가 화면을 덮어 조작이 안 된다.
2. `#setupGuide` 오버레이의 `hidden`을 풀어 4단계 안내를 띄운다.

```js
const SETUP_DONE = Boolean(SUPABASE_URL && SUPABASE_PUBLISHABLE_KEY);
if (!SETUP_DONE) document.getElementById("setupGuide").hidden = false;
```

오버레이 마크업은 JS로 만들지 않고 **HTML에 그대로 적어 두었다.** 학생이 읽고 고칠 수 있어야 해서다.

## SQL — 가르치려고 쓴 주석

`supabase/schema.sql`은 hd-08 것을 옮기면서 **왜 이렇게 하는지를 단계마다 적었다.**

- `check` 제약: 화면 검사는 개발자 도구로 우회되니 진짜 방어선은 여기라는 것
- RLS: publishable 키가 공개인데도 안전한 이유가 키가 아니라 규칙이라는 것
- `with check`를 빼면 남의 id로 바꿔치기하는 수정이 통과한다는 것
- `security definer` + `search_path = ''`가 무엇을 막는지
- 트리거의 `when` 절이 없으면 이 함수의 예외가 다른 사이트 가입까지 막는다는 것
- `revoke ... from public`만으로는 Supabase가 붙인 `anon`이 남는다는 것

**로컬 PostgreSQL 17로 검증했다.** hd-08의 하네스를 접두사만 바꿔 재사용했고,
2회 연속 적용(재실행 안전성) 후 ASSERT 17건 + updated_at 1건 전부 통과했다.
하네스 자체는 hd-08에서 `--break`로 이미 검증돼 있다.

## README를 자세히 쓴 이유

학생이 복사해 가면 **옆에서 설명해 줄 사람이 없다.** 수업 시간에만 되는 자료는 쓸모가 적다.
그래서 안내서 형식으로 썼다.

- 6단계 절차 — Supabase 가입부터 Pages 배포까지, 화면 메뉴 이름 그대로
- **키 두 종류 구분** — publishable은 공개돼도 되고 secret은 절대 안 되는 이유까지
- 바꿔야 할 곳 표 — 필수 2곳 / 선택 4곳, 그중 2곳은 **두 파일을 같이** 고쳐야 함을 강조
- 코드 읽는 순서 — 실제 함수명으로 7단계
- 잘 안 될 때 표 — 증상 → 원인 → 해결 12줄
- 확인 체크리스트 8개, 더 해보기 6개

**README에 적은 함수명은 실제 코드와 대조했다.** 처음엔 `checkPassword`·`loadProfile`·`updateProfile`로
썼는데 셋 다 없는 이름이었다. 실제로는 `inspectPassword`·`updatePasswordUI`·`refreshAccount`다.
"더 해보기"에 넣었던 비밀번호 재설정도 **이미 구현돼 있어서** 읽기 과제로 바꿨다.
안내서에 없는 이름을 적으면 학생은 자기가 잘못한 줄 안다.
