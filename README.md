# hd-03 · 회원가입 만들기 실습

로그인이 되는 웹사이트를 처음부터 끝까지 직접 만들어 보는 예제입니다.

서버 프로그램을 따로 만들지 않습니다. **HTML 파일 하나**와 **Supabase**라는 무료 서비스만 씁니다.
그런데도 실제 서비스에 들어가는 요소는 거의 다 들어 있습니다.

## 1. 무엇을 만드나

화면은 세 개입니다. 위쪽 탭으로 오갑니다.

| 화면 | 하는 일 |
|---|---|
| **회원가입** | 이메일·비밀번호·이름·휴대전화를 받아 계정을 만듭니다 |
| **로그인** | 만든 계정으로 들어갑니다 |
| **내 정보** | 로그인한 사람만 볼 수 있고, 자기 정보를 고칠 수 있습니다 |

눈에 잘 안 보이지만 이 예제가 실제로 다루는 것들:

- **입력값 검사** — 이메일 오타(`gmail.con` 같은), 일회용 메일 주소, 휴대전화 번호 형식, 비밀번호 강도
- **비밀번호 정책** — 길이·대소문자·숫자·기호를 실시간으로 표시
- **개인정보 동의** — 동의 시각까지 기록
- **RLS(행 수준 보안)** — 로그인해도 **남의 정보는 아예 안 보이게** 데이터베이스에서 막기
- **트리거** — 계정이 만들어지는 순간 데이터베이스가 알아서 회원 정보를 채우기

마지막 두 개가 이 수업의 핵심입니다. 화면에서 하는 검사는 개발자 도구로 얼마든지 우회할 수 있어서,
**진짜 방어선은 데이터베이스 쪽**에 있어야 합니다.

## 3. 따라 하기

전체 30~40분쯤 걸립니다. 순서대로 하세요. 건너뛰면 나중에 원인을 찾기 어렵습니다.

### 0단계 — 내 리포지토리로 가져오기

셋 중 편한 방법을 고르세요.

**방법 A. 파일 다운로드 (가장 간단)**
1. 이 페이지 위쪽 초록색 `Code` 버튼 → `Download ZIP`
2. 압축을 풀고 내 컴퓨터에 둡니다
3. 나중에 GitHub에 올릴 때 새 리포지토리를 만들어 파일을 넣습니다

**방법 B. 포크(Fork)**
1. 오른쪽 위 `Fork` 버튼
2. 내 계정에 복사본이 생깁니다

**방법 C. 클론(Clone)** — git을 아는 경우
```bash
git clone https://github.com/aebonlee/hd-03.git 내프로젝트이름
cd 내프로젝트이름
rm -rf .git      # 원본 이력을 지우고 내 것으로 새로 시작
git init
```

> **주의**: 어느 방법이든 **파일을 고치기 전에 먼저 내 것으로 가져오세요.**
> 이 리포지토리 자체는 여러분이 고칠 수 없습니다.

### 1단계 — Supabase 프로젝트 만들기

1. [supabase.com](https://supabase.com) 접속 → `Start your project` → GitHub 계정으로 로그인
2. `New project` 클릭
3. 입력할 것:

   | 항목 | 값 |
   |---|---|
   | Name | 아무거나 (예: `hd03-실습`) |
   | Database Password | **적어 두세요.** 나중에 다시 못 봅니다 |
   | Region | `Northeast Asia (Seoul)` — 가까울수록 빠릅니다 |
   | Plan | Free |

4. `Create new project` → 준비되는 데 1~2분 걸립니다. 기다리세요

---

### 2단계 — 주소와 키를 복사해서 붙여넣기

Supabase 대시보드에서 왼쪽 아래 톱니바퀴(`Project Settings`) → `API`로 갑니다.

두 가지를 복사합니다.

| 이름 | 생김새 | 어디에 |
|---|---|---|
| **Project URL** | `https://abcdefgh.supabase.co` | `SUPABASE_URL` |
| **publishable key** | `sb_publishable_` 로 시작하는 긴 문자열 | `SUPABASE_PUBLISHABLE_KEY` |

이제 `index.html`을 편집기로 엽니다. 파일 아래쪽(1030줄 근처)에 이런 표시가 있습니다.
편집기에서 `▼▼▼` 를 검색하면 바로 찾습니다.

```js
/* =====================================================================
   ▼▼▼ 여기 두 줄만 본인 값으로 바꾸면 됩니다 ▼▼▼
   ...
   ===================================================================== */
const SUPABASE_URL = "";
const SUPABASE_PUBLISHABLE_KEY = "";
/* ▲▲▲ 여기까지 ▲▲▲ */
```

따옴표 **안에** 붙여넣습니다.

```js
const SUPABASE_URL = "https://abcdefgh.supabase.co";
const SUPABASE_PUBLISHABLE_KEY = "sb_publishable_xxxxxxxxxxxxxxxx";
```

> ### ⚠ 여기가 제일 중요합니다 — 키 두 종류를 구분하세요
>
> 같은 화면에 **secret key**(또는 `service_role`)도 있습니다. **그건 절대 붙여넣지 마세요.**
>
> `index.html`은 브라우저로 그대로 내려갑니다. 누구나 소스 보기로 읽을 수 있습니다.
> secret key를 넣으면 그 사람이 **여러분 데이터베이스를 통째로 읽고 지울 수 있습니다.**
>
> publishable key는 **공개돼도 되도록 설계된 키**라 괜찮습니다.
> "그럼 아무나 데이터를 볼 수 있는 것 아닌가?" 싶겠지만, 그걸 막는 것이
> 다음 단계에서 켜는 **RLS**입니다. 키가 아니라 규칙이 막는 구조입니다.

### 3단계 — 데이터베이스 만들기

1. Supabase 왼쪽 메뉴에서 `SQL Editor` → `New query`
2. 이 프로젝트의 **`supabase/schema.sql` 파일을 열어 내용 전체를 복사**
3. 붙여넣고 오른쪽 아래 `Run` (또는 `Ctrl/Cmd + Enter`)
4. 아래에 `Success. No rows returned` 가 뜨면 성공입니다

무엇이 만들어졌는지는 `schema.sql` 안에 단계마다 주석으로 적어 두었습니다.
**그냥 실행만 하지 말고 한 번 읽어 보세요.** 이 수업에서 가장 배울 것이 많은 파일입니다.

> 여러 번 실행해도 안전하게 짰습니다. 뭔가 꼬였다 싶으면 다시 실행하세요.

---

### 4단계 — 이메일 로그인 켜기

1. 왼쪽 메뉴 `Authentication` → `Sign In / Providers`
2. `Email` 이 켜져 있는지 확인합니다
3. **연습 중에는 `Confirm email` 을 꺼 두세요.** 가입하자마자 바로 로그인돼서 훨씬 편합니다
   - 다 만들고 나면 다시 켜세요. 실제 서비스에서는 켜는 것이 맞습니다

그다음 `Authentication` → `URL Configuration`:

- `Site URL` 에 본인 사이트 주소를 넣습니다 → `https://<내아이디>.github.io/hd-03/`
- 아직 배포 전이라면 `http://localhost:8000` 을 넣어 두고, 6단계 뒤에 바꾸세요

### 5단계 — 내 컴퓨터에서 확인하기

`index.html`을 그냥 더블클릭하면 **안 됩니다.** 브라우저가 `file://` 로 열면 보안 규칙 때문에
Supabase 연결이 막힙니다.

작은 웹 서버를 띄워야 합니다. 터미널(윈도우는 PowerShell)에서 프로젝트 폴더로 간 뒤:

```bash
# 파이썬이 있으면 (맥은 기본 설치되어 있습니다)
python3 -m http.server 8000

# 윈도우에서 python3 가 없다고 하면
python -m http.server 8000
```

그리고 브라우저에서 **http://localhost:8000** 을 엽니다.

> VS Code를 쓴다면 `Live Server` 확장을 설치하고 `index.html` 우클릭 → `Open with Live Server` 가 더 편합니다.

**설정이 아직 비어 있으면** 화면에 초록색 안내 창이 뜹니다. 2단계를 안 했다는 뜻입니다.
안내 창이 안 뜨면 설정이 들어갔다는 뜻이니, 회원가입을 한번 해 보세요.

가입이 되면 Supabase 대시보드 `Table Editor` → `hd03_profiles` 에 내 정보가 한 줄 들어와 있어야 합니다.

### 6단계 — 인터넷에 올리기 (GitHub Pages)

## 4. 바꿔야 할 곳 정리

### 반드시 바꿔야 하는 것

| 어디 | 무엇 |
|---|---|
| `index.html` | `SUPABASE_URL` — 내 Supabase 주소 |
| `index.html` | `SUPABASE_PUBLISHABLE_KEY` — 내 publishable 키 |

이 둘만 바꾸면 동작합니다.

### 바꿔도 되는 것 (익숙해진 뒤에)

| 어디 | 무엇 | 주의 |
|---|---|---|
| `index.html` | `APP_NAME` — 화면에 보이는 서비스 이름 | 자유롭게 |
| `index.html` | `SITE_CODE` — 어느 사이트에서 가입했는지 기록용 | 자유롭게 |
| `index.html` + `schema.sql` | `hd03_profiles` — 표 이름 | **양쪽을 같이** |
| `index.html` + `schema.sql` | `hd03-membership-v1` — 트리거 조건 | **양쪽을 같이** |

> **표 이름과 트리거 조건은 두 파일에 같은 값이 들어갑니다.**
> 한쪽만 바꾸면 오류 메시지 없이 조용히 안 됩니다.
> 가입은 되는데 `hd03_profiles` 에 아무것도 안 들어오는 증상이 나옵니다.
> 찾기 제일 어려운 종류의 버그이니 바꿀 때는 꼭 양쪽을 확인하세요.

### 왜 이름 앞에 `hd03_` 이 붙어 있나

Supabase 프로젝트 하나에 여러 사이트의 표가 함께 들어갈 수 있습니다.
그냥 `profiles` 라고 지으면 다음에 만드는 사이트와 이름이 부딪힙니다.
그래서 사이트마다 짧은 접두사를 붙이는 습관을 들이는 것이 좋습니다.

## 5. 코드 읽는 순서

바로 다 읽으려 하지 말고 이 순서로 보세요.

편집기에서 함수 이름으로 검색하면 바로 찾을 수 있습니다.

| 순서 | 볼 곳 | 무엇을 하는 코드인가 |
|---|---|---|
| 1 | `supabase/schema.sql` | **여기부터.** 데이터가 어떻게 생겼고 무엇이 막혀 있는지가 다 있습니다 |
| 2 | `index.html` 의 `▼▼▼` 설정 블록 | 어떤 값이 어디에 쓰이는지 |
| 3 | `#signupForm` 의 `submit` 처리 | 가입 버튼을 눌렀을 때 일어나는 일 |
| 4 | `inspectEmail()` / `inspectPassword()` | 이메일 오타·일회용 주소 판별, 비밀번호 강도 계산 |
| 5 | `updateEmailInspection()` / `updatePasswordUI()` | 검사 결과를 화면에 그리는 부분 |
| 6 | `refreshAccount()` | 로그인 뒤 내 정보를 읽어 오는 부분 |
| 7 | `#profileForm` 의 `submit` 처리 | 내 정보를 고쳐 저장하는 부분 |

4·5번이 나뉘어 있는 데 주목하세요. **판단하는 코드와 화면에 그리는 코드를 분리**해 두면
나중에 규칙을 바꿀 때 한 곳만 고치면 됩니다.

### 알아 두면 이해가 빨라지는 것

**`raw_user_meta_data` 가 뭔가요**
가입할 때 이메일·비밀번호 말고 이름·전화번호도 같이 보냅니다.
그 추가 정보가 `auth.users` 표의 `raw_user_meta_data` 칸에 통째로 들어갑니다.
트리거가 그걸 꺼내서 우리 표에 옮겨 담습니다.

**왜 트리거로 하나요, 그냥 두 번 요청하면 안 되나요**
됩니다. 그런데 계정은 만들어졌는데 두 번째 요청이 실패하면
**계정만 있고 정보는 없는 회원**이 생깁니다. 창을 닫아도 마찬가지입니다.
데이터베이스가 한 번에 처리하면 그럴 일이 없습니다.

**RLS가 없으면 어떻게 되나요**
publishable 키는 공개된 키입니다. RLS를 안 켜면 그 키를 복사한 사람이
전체 회원 명단을 그대로 내려받을 수 있습니다. 실제로 자주 나는 사고입니다.

## 6. 잘 안 될 때

브라우저에서 **F12**(맥은 `Cmd+Option+I`) → `Console` 탭을 먼저 보세요.
빨간 글씨가 원인을 알려줍니다.

| 증상 | 원인 | 해결 |
|---|---|---|
| 초록색 설정 안내 창이 계속 뜬다 | `SUPABASE_URL`/`KEY` 가 비어 있음 | 2단계. 따옴표 **안에** 넣었는지 확인 |
| 화면이 하얗게 빈다 | JS 오류 | F12 콘솔의 빨간 줄을 읽으세요. 따옴표나 세미콜론을 지웠을 가능성이 큽니다 |
| `Failed to fetch` | 주소 오타, 또는 `file://` 로 열었음 | URL 끝에 `/` 없이 `.supabase.co` 로 끝나는지 확인. 5단계처럼 서버로 여세요 |
| 가입 버튼을 눌러도 반응이 없다 | 필수 항목 미입력 | 빨간 글씨가 뜬 칸을 확인하세요 |
| `User already registered` | 이미 가입한 이메일 | 다른 이메일로 하거나, `Authentication > Users` 에서 지우세요 |
| 가입은 되는데 `hd03_profiles` 가 비어 있다 | 트리거 조건 불일치 | `index.html`의 `SIGNUP_SOURCE` 와 `schema.sql`의 `when` 절 문자열이 **완전히 같은지** |
| 가입할 때 오류가 뜬다 | 트리거의 검사에 걸림 | 오류 문구를 읽으세요. 이름 2자 이상, 전화번호 `010xxxxxxxx` 형식입니다 |
| 로그인은 되는데 내 정보가 안 보인다 | RLS 정책 없음 | 3단계 SQL을 다시 실행하세요 |
| 메일이 안 온다 | 확인 메일 설정 | 4단계에서 `Confirm email` 을 끄면 메일 없이 됩니다 |
| 배포한 사이트만 안 된다 | `Site URL` 미설정 | 4단계의 URL Configuration 을 배포 주소로 |
| GitHub Pages가 404 | 아직 배포 중이거나 설정 안 됨 | 1~2분 기다린 뒤 `Settings > Pages` 확인 |

### 그래도 안 되면

Supabase 대시보드 `Logs` → `Postgres Logs` 를 보세요.
트리거에서 난 오류가 여기 그대로 찍힙니다.

## 8. 더 해보기

다 됐으면 하나씩 붙여 보세요. 위쪽일수록 쉽습니다.

1. **색과 문구 바꾸기** — `index.html` 맨 위 `:root` 의 `--brand` 색을 바꿔 보세요
2. **입력 항목 추가** — 생년월일이나 소속을 받아 보세요.
   `schema.sql` 에 칸을 더하고, 화면에 입력란을 만들고, 트리거에서 꺼내 담아야 합니다. **세 곳을 다 고쳐야 합니다**
3. **비밀번호 재설정 흐름 읽기** — 이건 이미 만들어져 있습니다.
   `resetPasswordForEmail` 을 검색해 보고, 메일을 받은 뒤 어디로 돌아오는지 따라가 보세요.
   4단계의 `Site URL` 설정이 왜 필요한지 여기서 이해됩니다
4. **소셜 로그인 붙이기** — Supabase `Providers` 에서 Google이나 Kakao를 켜고
   `supabase.auth.signInWithOAuth()` 를 써 보세요. 이 예제에는 아직 없습니다
5. **회원 탈퇴** — 계정을 지우면 프로필도 같이 지워집니다(`on delete cascade`).
   `schema.sql`에서 그 부분을 찾아보세요. 다만 **브라우저에서는 계정을 지울 수 없습니다.**
   왜 그럴지 생각해 보세요 (힌트: 그걸 할 수 있는 키는 브라우저에 두면 안 되는 키입니다)
6. **RLS를 일부러 꺼 보기** — `alter table public.hd03_profiles disable row level security;` 를 실행하고
   로그아웃 상태에서 데이터가 보이는지 확인한 다음, **반드시 다시 켜세요.**
   RLS가 무엇을 막고 있었는지 몸으로 알게 됩니다
